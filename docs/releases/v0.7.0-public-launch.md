# v0.7.0 preparation: candidate and limits

**Unpublished preparation draft, 2026-10-11.** The published release remains
v0.6.0. The version and installation references on this branch propose
v0.7.0; they become usable only after the maintainer completes the release
procedure. This document does not grant a merge, tag or publication.

## Changes proposed for this release

The candidate includes main through `35e74dc69b9a6582f5c8409d64027d61653acd2e`,
the imported-helper skip guard fix in [#362](https://github.com/taipei49314/checkwash/pull/362),
the Git input contract in [#365](https://github.com/taipei49314/checkwash/pull/365),
and the bounded JS/TS catch fix in [#368](https://github.com/taipei49314/checkwash/pull/368)
for [#363](https://github.com/taipei49314/checkwash/issues/363).

The changes merged since v0.6.0 include Python test-runner aliases and
configuration carriers, requested conftest/helper skips and guard sources,
assertion subjects, tolerance and expected-value provenance; JS/TS Chai,
AVA/TAP, iterator callbacks, alias specifiers, setup-file stand-ins, quoted
markers and parser performance; CI/composite runner controls; and opaque
submodule handling. The main history also records the #212 replay selection
and correction. These are bounded implementations with their existing
capability limits, not a general control-flow or runtime verifier.

The helper guard keeps the source of the guard and its unknown fallback.
The Git reader validates immutable objects and refuses failed or incomplete
required reads rather than reporting an ordinary pass. Its decimal limits
are unchanged. The JS/TS addition uses the existing `BROAD_EXCEPT_ADDED`
rule and severity: supported synchronous assertions swallowed by an added
catch produce a finding. Rethrows and supported preserving catch assertions
remain controls. See [the exact capability boundary](../js-catch-swallowing.md).

The package proposes version 0.7.0. The JSON finding interface remains
`checkwash_findings_version: 2`; new findings and refused inputs can change
results. Consumers must preserve exit 2 and diagnostics as analysis errors.
A pass still does not prove a change correct or honest.

## Try it on a change you understand

After publication, download `checkwash.pyz` from the v0.7.0 release and use
Python 3.11 or later:

```bash
python checkwash.pyz --version
python checkwash.pyz check BASE..HEAD --repo /path/to/repository --format json
```

Exit 0 means the configured gate passes, exit 1 means it blocks, and exit 2
means an input or analysis error. Retain stdout, stderr and the exit status.
Review findings in context before changing the test or recording an exemption.

The recommended Action advances to the published v0.6.0 commit
`8c70efbf93975bf3210acb8eafbaf4b38044a770` under the existing one-release lag.
Its engine does not contain this candidate's later changes. Upgrading the CLI
does not update a caller's Action pin. The Action engine's separate assertion
qualification is reported with its actual capability gaps.

## Open limits and deferred work

See [known issues](../KNOWN-ISSUES-v0.7.0.md) for evidence, affected scope,
workarounds and release disposition. #366 and #367 and the #364 collaboration
proposal are outside this release's fixed scope. Typed declaration headers,
labels, classes, async completion, unsupported control flow and callback
registration/invocation reachability remain outside the new catch proof.
Git worktree reads remain non-atomic and do not detect every change-and-revert.

The formal held-out/custody platform and protected historical materializer are
separate work. Neither is silently completed here. The materializer is not
rerun, retried, canceled or used to choose this release's cohort.

The release remains **WAITING_ON_DEPENDENCY** until final candidate artifacts,
applicable execution admission, complete fixed replays, adjudication and
necessary maintainer decisions are evidenced. Only then can a review packet
be marked `READY_FOR_OWNER_RELEASE_REVIEW`. Main merge, tag, publication,
post-publication gates and downstream re-pins are not performed by this draft.
